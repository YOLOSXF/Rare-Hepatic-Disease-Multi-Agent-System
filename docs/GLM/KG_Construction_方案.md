### 2.2 Milvus在KG系统中的预期作用与存储数据

#### 存储数据规划

| 存储内容          | 向量维度     | 嵌入模型   | Collection    | 用途            | 检索场景        |
| ------------- | -------- | ------ | ------------- | ------------- | ----------- |
| **EL4特征节点嵌入** | 1024-dim | BGE-M3 | `kg_entities` | 特征节点的语义向量表示   | 患者症状→相似特征匹配 |
| **EL3疾病节点嵌入** | 1024-dim | BGE-M3 | `kg_entities` | 疾病节点的综合描述向量   | 症状组合→候选疾病粗排 |

### 2.3 Milvus在检索管道中的位置

```
患者输入: "震颤、黄疸、铜蓝蛋白0.08g/L"
    │
    ▼
[BGE-M3嵌入] → 1024-dim向量
    │
    ▼
[Milvus COSINE搜索] ← Stage 1: 向量粗排
    │  collection: kg_entities
    │  metric: COSINE
    │  top_k: 20
    │  输出: Top-20相似实体 (如"K-F环"、"铜蓝蛋白降低"、"Wilson病")
    │
    ▼

    │
    ▼
[投票+排序] ← Stage 3: 确定候选疾病
    │
    ▼
[上下文组装] ← Stage 4: Token截断后注入LLM
```

**Milvus的核心价值**: 提供毫秒级的语义相似度检索，将患者描述从"自然语言空间"映射到"知识图谱实体空间"，是级联检索管道的第一道关卡。没有Milvus，系统只能依赖关键词匹配，无法处理同义词（如"肝豆状核变性"="Wilson病"）、近义描述（如"铜蓝蛋白低"≈"铜蓝蛋白<0.20g/L"）、口语化表述（如"眼睛有铜环"≈"K-F环阳性"）等语义变体。

**为什么不能用关键词匹配替代Milvus**:

| 患者输入     | 关键词匹配结果              | Milvus语义匹配结果               |
| -------- | -------------------- | -------------------------- |
| "铜蓝蛋白偏低" | ❌ 无法匹配"铜蓝蛋白<0.20g/L" | ✅ 匹配EL4d: 铜蓝蛋白降低 (相似度0.89) |
| "眼睛有铜环"  | ❌ 无法匹配"K-F环"         | ✅ 匹配EL4d: K-F环阳性 (相似度0.82) |
| "手抖说话不清" | ❌ 无法匹配"震颤+构音障碍"      | ✅ 匹配EL4d: 震颤 (相似度0.78)     |
| "肝豆状核变性" | ✅ 精确匹配               | ✅ 匹配EL3: Wilson病 (相似度0.95) |

## 3. 三层分离+四层诊断KG架构详解与样例

### 3.1 "三层分离"指哪三层

三层分离是知识图谱的**纵向分层架构**，将知识按稳定性和来源分为三层，借鉴自MedGraphRAG(P5)的Triple Graph Construction设计：

| 层级          | 名称                | 性质      | 数据来源          | 存储方式            | 当前状态                    |
| ----------- | ----------------- | ------- | ------------- | --------------- | ----------------------- |
| **Layer 3** | 本体层 (Ontology)    | 固定不变    | HPO本体(hp.obo) | NetworkX只读图     | ❌ **HPO文件未下载，暂未建设**     |
| **Layer 2** | 文献层 (Literature)  | 固定(版本化) | 指南PDF         | Neo4j + Milvus  | ✅ **当前唯一可建设层**          |
| **Layer 1** | 患者数据层 (User Data) | 动态(会话级) | 患者输入          | LangGraph State | ✅ **已有DiagnosticState** |

**三层分离的核心优势**:

1. **知识稳定性隔离**: 本体层和文献层是静态的医学知识，不会被单次诊断会话修改；患者数据层是动态的，每次诊断会话独立。这防止了诊断结果"反向污染"医学知识库。
2. **跨层引用(Triple Linking)**: 每个诊断特征关联三层信息——\[图谱实体, 来源文献, 标准定义]，实现可溯源推理。例如"铜蓝蛋白<0.20g/L"同时关联：EL4d节点(文献层) + CMA\_Wilson\_2022 §4(来源) + HP:0002194(本体定义)。
3. **独立更新**: 指南更新只影响文献层，HPO版本升级只影响本体层，互不干扰。例如EASL-ERN 2025指南发布时，只需更新文献层中Wilson病的EL4特征，不影响本体层或其他疾病节点。
4. **安全边界**: 患者数据不会污染医学知识，符合MedGraphRAG"RepoGraph is fixed"的设计哲学。每次诊断会话的患者数据在Layer 1独立维护，会话结束后不持久化到Layer 2/3。
5. **灵活降级**: 当某层不可用时，系统仍可运行。例如本体层(Layer 3)未建设时，用均匀权重替代IC值；文献层(Layer 2)不可用时，退回纯向量检索。

**当前约束下的调整**:

- Layer 3(本体层): HPO文件未下载，**当前阶段暂不建设**，后续下载hp.obo后接入。当前用均匀权重(所有特征IC值=1.0)替代HPO IC值。
- Layer 2(文献层): **当前唯一可建设层**，以指南PDF为数据源，LLM提取+人工审核。
- Layer 1(患者数据层): 已有DiagnosticState，无需额外建设。

### 3.2 "四层诊断KG"指哪四层

四层诊断KG是文献层(Layer 2)内部的**横向层级结构**，将疾病诊断知识按粒度从粗到细分为四层，借鉴自MedRAG(P3)的诊断KG设计：

| 层级      | 名称                 | 粒度 | 内容              | 示例                  |
| ------- | ------------------ | -- | --------------- | ------------------- |
| **EL1** | 疾病大类 (Category)    | 最粗 | 按病因/机制分类的疾病大类   | 代谢性肝病、自身免疫性肝病       |
| **EL2** | 疾病亚类 (Subcategory) | 中等 | 大类下的机制亚类        | 铜代谢障碍、铁代谢障碍         |
| **EL3** | 具体疾病 (Disease)     | 具体 | 可明确诊断的疾病实体      | Wilson病、AIH、PBC     |
| **EL4** | 诊断特征 (Feature)     | 最细 | 疾病的临床表现/检验/影像特征 | 铜蓝蛋白<0.20g/L、K-F环阳性 |

**四层诊断KG的核心优势**:

1. **贴合临床诊断推理**: 医生诊断时遵循"大类→亚类→具体病→鉴别特征"的推理路径，四层结构与之一致。例如：代谢性肝病(EL1) → 铜代谢障碍(EL2) → Wilson病(EL3) → 铜蓝蛋白<0.20g/L(EL4)。
2. **支持Top-down和Bottom-up双向检索**:
   - **Top-down(分诊路径)**: 从EL1向下定位，适合分诊场景。例如：患者主诉"黄疸"→ 代谢性肝病(EL1) → 铜代谢障碍(EL2) → Wilson病(EL3)
   - **Bottom-up(特征匹配路径)**: 从EL4向上投票，适合检验结果异常场景。例如：铜蓝蛋白0.08g/L(EL4) → Wilson病(EL3) → 铜代谢障碍(EL2) → 代谢性肝病(EL1)
3. **诊断差异KG**: 同一EL2下的EL3疾病可预计算`differential_from`边，直接提供鉴别要点。例如Wilson病与AIH同属EL2"自身免疫/代谢性肝病"下，预计算差异边包含4个鉴别点。
4. **可扩展**: 新增疾病只需在对应EL2下添加EL3节点+EL4特征，不影响已有结构。增量更新成本低。
5. **特征权重分层**: EL4特征分为核心特征(is\_core=true, 权重2.0)和支持特征(is\_core=false, 权重1.0)，核心特征对诊断决策影响更大。

### 4.3 关键发现（代码库验证版）

**发现1: 指南PDF是当前唯一权威数据源**

`data/guidelines/` 目录中仅有2份Wilson病指南PDF和1份罕见肝病目录docx：

- 中文指南：《肝豆状核变性诊疗指南（2022年版）》— 中华医学会肝病学分会
- 英文指南：《New EASL-ERN Clinical Practice Guidelines on Wilson's disease》2025 — EASL+ERN
- 其余5种罕见肝病(AIH/PBC/血色病/α1-抗胰蛋白酶缺乏症/PSC)均无对应PDF指南

**发现2: YAML规则未经验证，不适用于KG构建**

`rules/rare_diseases.yaml` 定义了6种罕见肝病的诊断规则（版本1.0.0，更新于2026-04-09），包含核心规则(core\_rules)、支持规则(supporting\_rules)、置信度阈值(thresholds)和输出建议(output)。但这些规则数据**未经肝病专家审核验证**，其中可能存在阈值不准确、规则不完整等问题。已发现的冲突包括：

- `guideline_verifier.py` 中铜蓝蛋白阈值为 `< 0.1`，与指南原文 `< 0.20 g/L` 不一致
- `evidence_chain.py` 引用2012版EASL指南，实际已有2025版
- `guideline_search.py` 中Wilson病曲恩汀为二线用药，EASL-ERN 2025已升级为一线

YAML规则继续用于分诊引擎的运行时模式匹配，但**不作为KG构建的数据源**。

**发现3: HPO本体文件尚未下载**

`hp.obo` 和 `phenotype.hpoa` 文件尚未获取。`hpo_extractor.py`中定义了默认搜索路径(`hpo/hp.obo`, `/data/hpo/hp.obo`)，但这些路径下均无文件。HPO提取器当前只能以降级模式运行（使用预定义的20个HPO ID映射和33个中文-英文术语映射）。本体层(Layer 3)当前无法建设。

**发现4: Milvus已配置但完全未接入（零数据存储）**

`config.yaml` 中存在Milvus配置（host: localhost, port: 19530, collection\_name: medical\_knowledge），但：

- `requirements.txt` 中 `pymilvus>=2.3.0` 被注释
- 代码中无任何 `pymilvus` 导入或调用
- 无嵌入模型代码（`SentenceTransformer`、`FlagEmbedding`等均未导入）
- `memory_retriever.py` 为空壳实现，`vector_db_path` 指向不存在的路径
- **Milvus中当前存储的数据量为0**

**发现5: Neo4j完全缺失**

无配置、无依赖、无代码。仅有设计文档。

**发现6: 数据源间覆盖度不一致**

三个结构化数据源之间存在覆盖范围不一致：

- `rare_diseases.yaml`: 6种疾病（含PSC）
- `rare_disease_db.py`: 5种疾病（**缺少PSC**）
- `guideline_search.py`: 4种疾病（**缺少PSC和α1-抗胰蛋白酶缺乏症**）
- 指南PDF: 仅1种疾病（Wilson病）

### 5.2 技术可行性详细评估

#### 5.2.1 方法A: 指南PDF驱动构建（推荐）

```
技术可行性评分: ★★★★★ (5/5)

优势:
  ✅ 数据权威性最高 — 指南PDF由权威医学机构发布，知识可信
  ✅ 知识覆盖全面 — 指南包含诊断标准、鉴别诊断、治疗方案、
     随访监测等完整知识链
  ✅ 可溯源性强 — 每条知识可关联到指南原文具体章节段落
  ✅ 适配当前约束 — 不依赖YAML(未验证)和HPO(未下载)
  ✅ 已有参考实现 — MedGraphRAG的LLM提取管道可直接移植
  ✅ 两份指南互补 — 中文指南提供中国临床实践基础，
     英文指南提供新指标+新药+更新推荐

劣势:
  ❌ LLM幻觉风险 — 阈值等精确数值可能被LLM错误提取
  ❌ 构建成本 — 每份指南需LLM调用(首次提取+Gleaning补充)，
     2份Wilson指南估计需50-80次LLM调用
  ❌ 人工审核必要 — 所有数值型阈值必须人工与指南原文比对
  ❌ 当前仅1种疾病有指南 — Wilson病有2份指南，
     其他疾病(AIH/PBC/血色病等)尚未上传指南PDF

关键风险及缓解:
  ⚠️ LLM阈值幻觉 → 人工审核所有数值型阈值
  ⚠️ 仅Wilson病有指南 → 先构建Wilson病KG作为原型验证，
     后续逐步补充其他疾病指南
```

#### 5.2.2 方法B: 多源融合构建（不推荐）

```
  ❌ HPO本体加载为Layer 3 → HPO文件未下载，不可用

  方案B的"多源融合"优势在当前约束下完全丧失:
  - YAML(占原方案数据量~40%)不可用
  - HPO(占原方案Layer 3全部)不可用
```

## 7. 检索性能对比分析

### 7.1 两方案检索策略对比

| 维度       | DEEPSEEK方案(级联检索)             | GLM方案(U-Retrieval+Bottom-up)   |
| -------- | ---------------------------- | ------------------------------ |
| **检索范式** | 管道式: 向量→图→投票→截断              | 交叉式: Top-down∩Bottom-up→子图→差异  |

| **精排机制** | Neo4j 1-hop + edge\_degree排序 | IC值加权投票 + 激活分数聚合               |
| **疾病定位** | shortestPath投票(4大类)          | Top-down分诊提示 + Bottom-up投票交叉验证 |
| **差异检索** | 运行时Cypher查询                  | 预计算differential\_from边直接查询     |
| **降级策略** | Neo4j不可用→Milvus纯向量→文本检索      | 无显式降级                          |

### 10.2 关键风险详细分析

#### R1: LLM提取的医学阈值不准确

**解决方案**:

```
1. 人工审核策略:
   ├── 所有数值型阈值(如铜蓝蛋白<0.20g/L)必须人工与指南原文比对

   │   ├── medium: LLM推断的数值(需人工确认)
   │   └── low: LLM生成的模糊描述(如"铜蓝蛋白降低")
   └── 仅confidence=high的阈值进入KG，其余标记待审核

2. Triple Linking溯源:
   每个阈值节点关联指南原文:
   {
       "value": 0.20,
       "unit": "g/L",
       "operator": "<",
       "source": {
           "guideline": "CMA_Wilson_2022",
           "section": "4. 实验室检查",
           "page": 5,
           "original_text": "血清铜蓝蛋白 < 0.20 g/L"
       },
       "confidence": "high",
       "verified_by": "人工审核"
   }

3. YAML交叉参考(仅参考,不作为权威):
   LLM提取的阈值与YAML中的阈值比对，
```

## 11. 推荐技术方案

### 11.1 方案概述

**方案名称**: 指南PDF驱动的四层诊断KG构建与级联检索方案

**核心设计原则**:

1. **指南PDF为唯一权威数据源** — 所有KG知识从指南PDF提取，不经YAML等未验证数据源
2. **LLM提取+人工审核** — LLM负责从PDF中提取结构化知识，人工审核所有数值型阈值
3. **YAML仅作运行时参考** — YAML规则继续用于分诊引擎，不进入KG
4. **HPO本体后续接入** — 本体层标记为待建设，当前用均匀权重替代IC值
5. **预计算优于运行时计算** — 诊断差异边在构建时预计算
6. **渐进式集成** — Feature Flag控制，可随时回退
7. **三级降级** — Neo4j不可用→Milvus纯向量→文本检索

```
│           推荐方案: 增强级联检索管道                                    │
```
